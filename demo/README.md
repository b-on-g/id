# $bog_id

Единый вход на Гипер Базе. Приложение не получает ключ пользователя: оно показывает свой Pass, а Гипер ID выдаёт ему права на отдельный ленд.

## Поток

1. Приложение генерирует свой ключ, как обычно: `$giper_baza_auth.current()`.
2. `$bog_id_login( provider, pass, scope )` открывает попап Гипер ID.
3. Попап шлёт `{ bog_id: 'ready' }` открывшему окну, получает `{ bog_id: 'request', pass, scope }`. Origin приложения берётся из `event.origin`, а не из сообщения.
4. Пользователь разрешает. Гипер ID заводит на пару `origin + scope` зашифрованный ленд, где правит сам, и делает `give( pass, post )`.
5. Приложение получает `{ lord, land }` и пишет в `land`.

Тот же сайт с другого устройства приходит с другим Pass и получает права на тот же ленд. Отзыв даёт `deny` всем Pass этого гранта.

## Для других фреймворков

`$bog_id_login` зависит только от DOM. Нужна Гипер База из npm, чтобы иметь свой Pass и читать выданный ленд.

```js
const { lord, land } = await $bog_id_login( 'https://b-on-g.github.io/id/', pass, 'notes' )
```

## Модули

- `bog/id` схема: `$bog_id_grant`, `$bog_id_store`
- `bog/id/login` функция входа для приложения
- `bog/id/app` провайдер: согласие, список подключённых приложений, отзыв
- `bog/id/demo` приложение с заметкой в выданном ленде

## Локально

Провайдер и демо должны жить на разных origin, иначе у них общий ключ в `localStorage`:

- провайдер: `http://127.0.0.1:9080/bog/id/app/-/index.html`
- демо: `http://localhost:9080/bog/id/demo/-/index.html`, в поле «Провайдер» адрес выше
